Why "Failed to fetch" — the CORS problem explained
▼ Root cause
Browsers block all API calls made from a local file:// page to external servers.
This is called CORS (Cross-Origin Resource Sharing) — a browser security policy.
The Massive API returns correct data, but the browser never lets the response through.
This is why your Massive dashboard shows zero hits — requests never leave the browser.
▲ Current fix applied — CORS proxy
This portal auto-detects file:// protocol and routes all requests through
corsproxy.io — a free public CORS proxy. Your API key is embedded in the URL,
which is safe for personal/desktop use. Requests now reach Massive and will show in your dashboard.
Option 1 — CORS proxy (already active, simplest)
active now
The portal already uses corsproxy.io automatically when opened from file://.
Just make sure your API key is set and click Refresh.
Requests will appear in your Massive dashboard within seconds.

If corsproxy.io is down, try replacing CORS_PROXY in the script with:
https://api.allorigins.win/raw?url=
Option 2 — Local server (best for daily use, no proxy needed)
Run ONE command in your terminal — no install required if you have Python or Node:
Python (built into macOS/Linux)
cd /path/to/folder/containing/dashboard
python3 -m http.server 8080
→ then open: http://localhost:8080/regime-compound-dashboard.html
Node.js
npx serve .
→ then open the localhost URL it gives you
VS Code (easiest)
Install Live Server extension → right-click the HTML file → Open with Live Server
When served from localhost, the browser allows external API calls freely.
Set NEEDS_PROXY = false at the top of the script if using local server — or leave it auto-detect.
API key check
Your key is set in the MASSIVE_KEY variable at the top of the <script> tag.
Get or copy your key at: massive.com/dashboard/keys
